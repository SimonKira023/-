# 答辩演示脚本（8 分钟 + 2 分钟提问）

> 目标：让评委记住一句话——**"别人做 AI 聊天，我们让 AI 拥有一个可以走进去的 3D 数码世界，而且光影就是游戏里的原样。"**

## 0. 演示前 5 分钟检查清单

- [ ] `start.bat` 已启动服务，Chrome 打开 `http://127.0.0.1:8787`，首屏能进
- [ ] 三个场景都点过一遍（商店 / 办公室 / 便利店），确认全景加载正常
- [ ] 右下角状态为"本地知识库"或"大模型讲解"，确认可用
- [ ] 关闭系统通知；浏览器全屏（F11）；输入法切英文
- [ ] 断网兜底：本地服务不依赖外网；另备 2 分钟录屏
- [ ] 试一次「自主巡展」（点顶部按钮，约 30 秒走完 5 站并自动出报告）
- [ ] 确认「行动轨迹」能展开，能看到工具调用步骤
- [ ] 确认右下角状态为「在线 · 大模型讲解」（.env 已配 DeepSeek；改完刷新页面即可）
- [ ] 大模型偶发超时时会自动回退本地引擎，演示不会中断
- [ ] 计时器：目标 7′40″ 讲完

## 1. 8 分钟分段脚本

> 提示：现在打开网页**默认就是 3D 漫游**（Godot Web 原场景）；点顶部 × 后进入 360° 实景看展品。

### 0:00 – 1:10 ｜ 痛点
> 大家好，我们做的是《数码考古馆》。
> 每个人家里都有淘汰的旧电脑、旧手机。它们不是垃圾，是**一代人第一次接触"数码"的证据**。但今天的孩子不知道软盘是什么，博物馆的展签又是静态的、没人看。
> 我们的问题：**能不能让老物件自己开口讲它的一生？**

### 1:10 – 2:10 ｜ 方案
> 我们复原了三个 360° 展厅：1980 年的街角五金商店、1994 年的东京办公室、海边小镇的便利店，一共 15 件展品。
> 重点不是全景，而是**馆里住着一个 AI 讲解员"小奖"**：它不是只会聊天，它有一双手——能自己切展厅、转头、变焦、高亮展品，然后开口讲解。
> 一句话：**观众用嘴参观，Agent 用镜头带队。**

### 2:10 – 5:40 ｜ 现场演示（最重要）
> 演示 1：我说 **"带我去看 CRT 电脑"** → 画面自动切到 1994 办公室、转头到电脑前、展品卡弹出，小奖开始讲"大头显示器、软驱、开机自检"。
> 演示 2：我说 **"带我去看自动售货机"** → 切到海边便利店，镜头对准售货机。
> 演示 3：我说 **"算盘和计算器有什么不同"** → 小奖做器物对比，并切换场景带我看实物。
> 演示 4：展开刚才回答上方的 **"小奖的行动轨迹"** → 评委能看到它先"理解意图"、再"检索知识库"、然后"切展厅/转头定位"，一步一个勾。
> 演示 5：点顶部 **"自主巡展"** → Agent 自己规划 5 站、自己切场景、自己讲解，进度条走"第 1/5 → 5/5 站"；结束后自动弹出 **参观报告**（场景数/展品数/时间线/一句话总结），可复制或下载。
> 演示 6：点 **"数码进化树"** → 算盘 → 收音机 → 电视 → 电话 → CRT 电脑 → 手机，点节点直接跳展品。
> 演示 7：打开顶部「🎥 摄像机」或说打开摄像机 → 进入 4:3 取景，拖动环视、WASD 移动、滚轮变焦，按空格拍照，展示左下角底片条：画面是 VHS/Video8 的扫描线、色差、日期戳；再说"拉近一点、调亮一点"，AI 会改镜头参数；切到「专家模式」，展示焦距/光圈/快门/ISO/白平衡，并输入"我想要电影感、稍微暗一点"，AI 换算整套参数。
> 强调：刚才所有镜头动作、路线选择、报告内容都不是我点的，是 Agent 根据一句话自己规划、自己执行的；摄像机则是把当年的观感做成可交互的第一人称取景。

### 5:40 – 6:40 ｜ 技术：光影和 Agent 怎么来
> 技术上两句话：
> 第一，**光影是游戏原样**——我们没有在网页里重新打光，而是用 Godot 加载游戏原始场景，脚本渲染 6 个 90° 立方体面，再拼成 6144×3072 全景；网页只做球面采样和转头。所以卡通描边、夕阳、天空、后期全是游戏里的原始渲染。
> 第二，**Agent 用工具调用**——`switchEra / goto / highlight / search / compare`，模型只输出结构化动作，前端做白名单校验，最多 6 步；没有 Key 或断网时自动降级本地规则引擎，现场演示不会死。

### 6:40 – 7:40 ｜ 价值与展望
> 价值三层：
> ① 对个人：抢救家庭数码记忆；
> ② 对教育：一个可复制的"数字博物馆"模板，学校、社区都能用；
> ③ 对商业：品牌可以做自己的产品历史馆、线下展的 AI 导览。
> 下一步：手机拍照识别老设备、语音讲解、多人同游。

## 2. 评委提问预判（准备答案）

| 问题 | 回答要点 |
|---|---|
| 这和普通 AI 问答有什么区别？ | 普通问答只输出文字；我们的 Agent 有工具，能**操作视角/切换展厅/高亮展品**，是"具身"的讲解员 |
| 光影真的是游戏里的吗？ | 是。流程：Godot 加载原场景 → 固定机位渲染 6 个立方体面 → 拼全景 → 网页球面采样；没在网页重新打光 |
| 年代是随便定的吗？ | 不是。海边便利店定为 1987：售货机 1970–80s 普及、JAN 条码 1978 标准/1982 年 7-Eleven POS、冷柜 1970–80s、自动门 1970s、Video8 1985；逐件列了来源，见 docs/年代考据.md |
| 摄像机的画面为什么是老的？ | 自定义后处理：4:3、桶形畸变、色差、扫描线、颗粒、暗角、暖调 + 日期戳；三个年代分别标注 VHS/Video8/Hi8 |
| 使用模拟是真的交互吗？ | 是。Canvas 逐帧绘制 + Web Audio 实时合成音效；15 件展品各有独立模拟，不是视频播放 |
| 真 3D 走动怎么保光影？ | 用 Godot Web 导出整个场景（wasm+pck），天空/水面/描边/灯光/后期都是游戏 shader，网页里直接跑原场景 |
| 镜头能看多近？ | 每件展品按尺寸设置 fov 16–26（如传真机 24、挂钟 20、灯塔 16），保证看得到物件细节 |
| 专家模式参数是真的吗？ | 焦距按 36mm 等效换算 fov，ISO 影响颗粒，快门影响拖影与曝光，光圈影响暗角，白平衡影响冷暖；增距镜/ND/偏振镜都有物理依据；不是装饰滑杆 |
| 为什么数码变焦糊？ | 只是裁切放大，没有新信息；真正拍远靠长焦玻璃/增距镜（更重更贵、光圈变小，但清楚） |
| 自由视角能走多远？ | 全景在固定机位渲染，移动范围限制在小幅游移，避免穿帮；这是"自由看"与"光影保真"的折中 |
| 为什么用全景而不是实时 3D？ | 游戏场景用了卡通描边、天空/水面 shader 和后期，WebGL 重写会失真；全景保证 100% 原样，而且加载小、低端设备也流畅 |
| 怎么防止 Agent 乱操作？ | 工具白名单 + 参数校验（展品 id 必须在知识库）+ 单次最多 6 步 + 本地兜底 |
| 这算 Agent 还是套壳聊天？ | 有工具（能操作视角/切场景）、有规划（plan 轨迹可见）、有记忆（localStorage）、有自主模式（自主巡展），还有 24 条指令的评测集与通过率 |
| 记忆和报告存在哪？ | 浏览器 localStorage，不上传服务器；报告可复制/下载，适合隐私敏感场景 |
| 讲解内容可靠吗？ | 展品卡是人工整理的年代/价格/生活背景，Agent 只做检索与组织；大模型模式也限定在知识库范围内回答 |
| 素材哪来的？有版权问题吗？ | 三个场景来自我们自己的游戏项目；公开仓库只放代码 + 自产/CC0 素材，第三方素材不入库并在 README 说明 |
| 用户价值/商业化？ | 数字展馆模板、品牌历史馆、线下展 AI 导览、校园/社区数字记忆项目 |
| 现在完成到什么程度？ | 三场景 15 件展品、Agent 五工具、路线与进化树全部可用；上线前还需补海报/视频 |

## 3. 演示失败兜底

1. 页面打不开：切桌面录屏（2 分钟版）
2. 大模型超时：页面自动用本地规则引擎（右下角显示"本地知识库"），行为一致
3. 现场网络断：本地服务不需要外网，全景图在本地
4. 时间不够：只演示"带我去看 CRT 电脑" + 进化树两个点
